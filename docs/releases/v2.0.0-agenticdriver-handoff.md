## Contract and migration

`/v1/providers`, `/v1/usage`, and `/v1/usage/:instanceId` stay supported.
There is no `/v1/limits` route, no new HTTP major version, and no application
login migration. Native administrative readback does not provide application
user authorization; retain explicit application-to-provider-instance mappings.

Use the SDK correction at `88daf7e52a956621389846e997a275ad97f9ae4a`, or a later
SDK release containing it. Published SDK `0.2.0-rc.1` still has the optional
quota adapter defect. It must not be overwritten. The corrected adapter derives
`agenticdriver.usagestat-limits.v1`; consumers validating the former
`crossusage.limits.v1` literal must update. Missing usage remains unknown;
failed cached or malformed observations must not become available quota.
Native desktop readback already used the correct routes.

Opt-in run ingestion is now present in the published backend:

- Handshake `/v1/run-usage/protocol`: `usagestat.run-ingestion.v1`, accepting
  only `agenticdriver.usage.v2`, receipt `usagestat.run-receipt.v1`, 65,536-byte
  event limit, and `requiresAccount=true`.
- Exact host/provider/account/subject binding and separate backend bearer
  credentials; no provider-family fallback and no provider-token reuse.
- Durable SQLite capture before acknowledgement; identical retries deduplicate,
  changed payloads conflict. Forwarding retries never rerun models.
- Usage/observed usage and coverage preserve unknown and partial measurements.
  Cache tokens are subsets; API-equivalent estimates remain separate from billed
  charges. Run records are not added to subscription quota/daily totals.
- Older event schemas are rejected. Provision exact bindings deliberately and
  perform the handshake before enabling capture. See [run ingestion](../run-ingestion.md).
- No existing readback route was removed. `/v0/management/*` remains optional
  T3 compatibility, separate from the native contract.
